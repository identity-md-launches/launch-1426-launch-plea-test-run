# PLEA Sepolia test run 3 adaptation

The input already contained the accepted run-2 adaptation, its audit fixes, and the requested run-3 contracts and tests. This submission retains that implementation and changes only reproduced defects and the manifest encoding/code commitment. No deployment or broadcast was made from this worker.

## Supplied audit findings

1. **Unanswered APPEAL letters with lazy expiry** (`e536cc603212c4f87f10dd183ff405e58879787ce64cca783bb2a433782c0bb4`). Reproduced in both oracle-fee modes: after the 20-minute timeout, the newest appeal still has `Pending` status and another APPEAL letter reverts `NotDenied`. The same failure occurs when Intake completes but its callback fails. In `src/Letterbox.sol`, `_appealTarget` now recognizes a settleable pending appeal as well as an expired appeal and selects its denied original. The existing `_settleOpen` then expires and refunds the stale escrow and tip before opening the retry, atomically. The original four-hour appeal window, single answered appeal, and fees are unchanged. Regressions: `test/AuditImported.t.sol` checks lazy timeout and completed-request/failed-callback retries, including escrow custody and tip refunds, in minted and purchased oracle-fee modes.

2. **Balance growth removes the appeal right** (`bf7d545f9e1ea550d02b0e74c8df2906c56340390c2e8c638ac74ca13dc6cedb`). Reproduced for direct gate appeals, raw APPEAL letters, and `appealAuto`: a larger balance raises the 1% minimum above the original amount, making every appeal amount invalid. In `src/CabalGate.sol`, `_open` saves the pre-escrow balance privately. `_appeal` applies `_checkAmount` using the lesser of that original balance and the current balance. This preserves the original 1% minimum when a balance grows and the existing current-balance minimum when it shrinks. The original amount already satisfied its own 50% ceiling, so combining the lesser balance with the separate original-amount limit preserves the current 50% ceiling too. Zero amounts, dust below the applicable minimum, amounts above the denied original, and amounts over 50% of the current balance remain refused. The 2.5M cap, scoring on the current balance, and all new-plea rules stay unchanged. The private mapping adds no public ABI field or selector. Regressions: `test/AuditImported.t.sol` covers all three appeal paths, original-minimum boundaries, smaller balances, and both fee modes. All ten initial reproduction cases failed on the imported code with the reported errors.

3. **Boolean manifest encoding** (`f8be2c6e0b568d45b1b96ade20cb822b780d219373792a77a26e9d9b513a605b`). The imported `launch.json` encoded `mintOracleFee` as the string `"true"`. That is outside the supplied recipe's decimal/hex static-word convention. Changed only that argument to `"1"`, which ABI-encodes the same boolean and preserves Sepolia oracle-fee minting. `test/LaunchManifest.t.sol` now asserts the manifest's static word and its ABI equivalence to the configured boolean. The deployer's parser is absent from this repository, so an actual downstream refusal could not be reproduced; the encoding mismatch itself is confirmed and repaired without assuming undocumented parser leniency.

## Additional reproduced owner-exclusion defect

`test/AuditOwnerTip.t.sol` reproduced a keeper-tip bypass after `PLEA.transferOwnership`: the hook checked only its immutable original owner, so the current PLEA owner received 0.01 IMD from `rebalance`. In `src/PleaHook.sol`, `_payTip` now also excludes `IPLEA(plea).owner()`. This implements the brief's explicit exclusion of the PLEA owner, including ownership transfers. The immutable fee beneficiary and existing exclusion of that original owner stay unchanged, as do the tip amount, work threshold, interval and wall accounting. The regression compares the same keeper/work before and after ownership transfer, proves an ordinary holder still earns the tip, and proves the new PLEA owner earns none.
